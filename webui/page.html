Recommended research workflow

  1. Call list_skills to enumerate the 79 finance knowledge skills, then load_skill("<name>") for any technique-heavy question.
  2. Frame the user's prompt as a research goal with start_research_goal, attach evidence with add_goal_evidence as you go.
  3. Pull data with get_market_data, get_fund_flow, get_dragon_tiger, get_northbound_flow, get_sec_filings, get_financial_statements, screen_market, web_search, etc.
  4. Analyse with backtest, factor_analysis, analyze_options, pattern_recognition, analyze_trade_journal.
  5. Visualise with render_shadow_report (8-section HTML/PDF) or the upstream Vibe-Trading REST frontend.
  6. Validate with run_shadow_backtest and scan_shadow_signals (research-only).

⚠ Safety guardrails (HARD RULES)

  1. The Vibe-Trading MCP server exposes zero order-placement tools. trading_* tools are read-only by design.
  2. Live-trading connector profiles (IBKR local TWS/Gateway, Robinhood MCP OAuth, Futu, Trading 212) are opt-in via the upstream CLI, not via MCP.
  3. run_swarm costs LLM tokens — always confirm with the user before spawning a multi-agent team.
  4. Always cite data source + timestamp in the final answer. Distinguish live-data facts, backtest results, and alpha-zoo statistics.
  5. Never claim live-trading readiness from a backtest alone. Surface overfitting, regime change, and survivorship bias explicitly.
