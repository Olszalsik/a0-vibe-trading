Vibe-Trading — Settings

MCP server

Uncheck to keep the plugin files installed but stop exposing the live MCP tools to the agent (74 at upstream v0.1.15; the exact number is probed live below).
Console script installed by pip install vibe-trading-ai. Override only if you wrap the server in a sidecar venv.
JSON array, e.g. ["--verbose"]. Rarely needed.

LLM provider (only used by run_swarm multi-agent teams)

All other MCP tools do not consume an LLM key.
Free-form; use the exact model id your provider expects. OpenAI gpt-5.6 models: upstream auto-retries tool calls on /v1/responses (reasoning models refuse function tools over chat completions), so no special configuration is needed.
0.0 is the upstream default. MiniMax requires > 0.
Hard cap on a single LLM call inside Vibe-Trading. Default 120.

Data source keys (all optional)

Without these, Vibe-Trading uses the free yfinance / stooq / yahoo / akshare / baostock / sina / eastmoney / mootdx / OKX chain with auto-fallback.
Sign up at tushare.pro. Free tier works for daily bars; higher tiers for fundamentals/limit-up data.
Caches settled historical bars under ~/.vibe-trading/cache/loaders/ so repeated backtests skip the network. Disable to force a fresh fetch every run.

QVeris premium data (explicit-only, default off)

QVeris is upstream's paid data track: with a key set, three key-gated tools (qveris_search / qveris_inspect / qveris_execute) unlock 63+ premium providers with preview-by-default and a session budget gate. No key = no cost, and QVeris never enters the auto-fallback chain — free public data stays the default. Other data modes (e.g. vibe-trading data mode paid) are managed by the upstream CLI.

Gildata (恒生聚源) A-share (optional, token-gated)

Gildata joins the tail of the A-share fallback chain with forward, split-AND-dividend adjusted daily bars (split_dividend caliber). Without a token the loader reports unavailable and the chain skips it — no behavior change for existing setups.
JSON object mapping market → comma-separated source order, passed to the MCP server as MARKET_DATA_ORDER_* env vars (upstream 0.1.15+). Markets: A_SHARE, US_EQUITY, HK_EQUITY, INDIA_EQUITY, KR_EQUITY, CA_EQUITY, VIETNAM_EQUITY, CRYPTO, FUTURES, FUND, MACRO, FOREX, INDEX. Empty = the upstream default fallback chain. Migration note (Gildata): an A_SHARE order saved before gildata joined the chain is a permutation of the old 7-source chain and stops validating — re-save it including gildata, or clear the field to fall back to the default order.

Risk guardrails

The Vibe-Trading MCP server never exposes order-placement tools. The risk tier is a soft policy the agent must respect; you can override per session.
Soft cap the agent uses to decide when to pause and re-confirm with you. Not enforced at the MCP layer.
Even with a live connector profile, the agent must surface every action for your OK before any tool is allowed to act on it.

Trade journal

Where the Journal page reads your roundtrips from.
Path to a broker-exported CSV of closed roundtrips. When set and the file exists it wins; otherwise the newest CSV uploaded on the Journal page is used; failing that, demo rows.
When on and no journal CSV path is configured, the Journal page shows the most recent file uploaded via its CSV upload card.
Saved. Restart Agent Zero to pick up the new MCP server config.
